# Frontend

Svelte 5 + TypeScript app built with Vite, dependencies installed through Deno's
`node_modules` compatibility mode.

```
frontend/
├── src/
│   ├── App.svelte         # layout, tabs, controls, transcript panel
│   └── lib/
│       ├── api.ts         # HTTP/SSE/WebSocket client, VadTranscriber, prewarmVad
│       ├── recorder.ts    # MediaRecorder wrapper
│       ├── wav.ts         # decode + downmix + resample to 16 kHz mono WAV
│       ├── languages.ts   # language table for the selectors
│       └── Icon.svelte    # inline icon set
├── public/                # VAD assets are copied here by `deno task copy-assets`
├── deno.json              # tasks: dev / build / check / copy-assets
└── vite.config.ts         # dev proxy to the API
```

## UI

Four mode tabs plus a transcript panel underneath:

| Tab | Description |
| --- | ----------- |
| **Live** | Real-time mic transcription with Silero VAD activity meter |
| **Plain text** | Record or upload → plain transcript |
| **Timestamped** | Record or upload → transcript + word/segment timings |
| **Long form** | Record or upload → long-form transcript |

The panel header names the model this instance serves (`parakeet-ultra`,
`canary-1b-v2`, …) with its precision, and the browser tab title repeats it —
two instances on two ports are otherwise indistinguishable. The label comes from
`GET /health` (`served_model`, falling back to the basename of a local `.nemo`
path), the tooltip carries the loaded path/id, dtype and live-stream slots, and
the trailing note reflects whether the model takes language arguments.

Language selectors (source → target, with a swap button) appear at the top when
the loaded model supports them, and are disabled while live transcription is
active. The transcript panel shows a word count and offers copy, download
(`.txt`) and clear actions; word/segment timings that a mode returns are rendered
below the transcript.

Audio can be recorded in the browser or dropped onto the drop zone (WAV, MP3,
M4A, WEBM, …) — everything is decoded, downmixed to mono and resampled to 16 kHz
client-side before upload. If the backend cannot be reached, a notice appears
above the controls.

## Live transcription

The Live tab uses the [Silero VAD](https://github.com/ricky0123/vad) browser
library (ONNX Runtime Web, v5 model) to detect voice activity locally:

1. Opening the tab already starts `prewarmVad()`, which fetches the model,
   worklet and wasm into the HTTP cache (see below).
2. Click **Start** — the VAD instance is created and a WebSocket connection is
   opened to `/v1/transcribe/stream`.
3. The VAD runs on every audio frame (512 samples / 32 ms) and shows a
   **probability meter** that fills green→red as speech likelihood rises. A
   pulsing dot indicates active speech.
4. Only frames where speech is detected are forwarded to the server as PCM-16 /
   16 kHz binary frames; silent intervals are dropped. A short pre-roll of frames
   is kept so the onset of speech is not clipped.
5. The server streams back `partial` events (shown in italic grey) and
   `committed` events (appended to the transcript) in real time.
6. When the VAD detects that the user stopped speaking it waits for the
   **commit delay** (slider, 200–1 000 ms, default 500 ms) and then sends
   `{type: "end"}`. The server finalises the segment, emits a `final` event and
   closes the connection; the client reopens it for the next utterance.
7. The status label cycles through **Listening…** → **Speaking…** →
   **Committing… (N ms)** → **Listening…**. Click **Stop** to end the session.

The streaming parameters sent with each session (`STREAM_PARAM_DEFAULTS` in
`api.ts`) are model-dependent; the shipped values are tuned for a transducer and
the reasoning is in [benchmarks.md](benchmarks.md#live-streaming-tuning).

## VAD assets

`deno task copy-assets` copies three files from `node_modules` into `public/`:
`silero_vad_v5.onnx`, `ort-wasm-simd-threaded.wasm` and
`vad.worklet.bundle.min.js`. They are gitignored and regenerated by `dev`/`build`.

They are served by the API image, which precompresses them at build time and
serves `.gz` siblings with a week of `Cache-Control`; `prewarmVad()` in `api.ts`
(triggered when the Live tab opens, and awaited by `start()`) makes sure the
download happens before the user clicks the mic. Adding a VAD asset means
updating `copy-assets` in `deno.json`, the prewarm list in `api.ts`, and
`_cache_control` in `server/app/main.py` if the new file has a different name
pattern.

The VAD runs in an AudioWorklet with ONNX Runtime Web in single-threaded mode, so
no Cross-Origin-Isolation (COOP/COEP) headers are required, and inference on
32 ms frames stays well inside the real-time budget on modest hardware.

## Development

```bash
deno install
deno task dev      # copy-assets + Vite dev server on :5173
deno task build    # copy-assets + production bundle into dist/
deno task check    # svelte-check (Svelte + TypeScript diagnostics)
```

The dev server proxies `/v1` and `/health` to `API_PROXY_TARGET`
(`http://localhost:9000` by default, `http://server:9000` under compose), so the
browser always talks to its own origin. `VITE_API_BASE` overrides that and points
the browser at a different origin directly. With the production image there is
nothing to configure: `STATIC_DIR` serves the bundle from the API port.
